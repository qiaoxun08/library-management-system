# 图书馆系统全站完美化审查方案 v6.0

> 目标：把网站做到最完美的状态。以苹果 UI 设计师视角 + 液态玻璃设计理念 + xunqiao 项目设计规范，
> 审查每一个用户能看到的页面，功能显示全部正常，设计达到可交付质量。
> 本文档是唯一执行依据，按 Step 0 → 7 顺序执行，不跳步。

---

## 一、三条判断标准（整改以这三把尺子量）

### A. 苹果级 UI
1. 按下瞬间（pointer-down / hover / active）有反馈，所有可点击实体（按钮、卡片、菜单项、行）都有按压态
2. 每个数值可推导：间距、字号比例、圆角成体系，不拍脑袋
3. 一屏一个主角：主按钮（prominent）唯一，其余降级
4. 热区 ≥ 44px：图标按钮、行内操作按钮可点击面积足够
5. 层级用深度表达：阴影克制统一，不叠罗汉

### B. 每屏三态 + 导航
1. 加载态：骨架屏 / loading 带脉冲，禁止静态色块干等
2. 空状态：统一 Empty 风格（图标 + 一句话 + 可选操作），禁止裸「暂无数据」
3. 错误态：inline 展示 + 可重试，禁止只 toast 后白屏
4. 表单：提交有 loading/反馈，校验错误就近显示

### C. 液态玻璃（克制版，适配 Element Plus 管理系统）
1. 玻璃只属于浮层（侧边栏顶栏悬浮态、下拉、弹窗、吸顶栏）；内容区保持实色纸感底
2. 透明度按上下文分档：含文字的面更实，纯图标浮层可透
3. 暗边 + 轻高光制造深度分离：浮层 1px 半透明描边 + 单层柔和阴影
4. 动效只用 transform/opacity，入场快于退场（进 ~300ms，出 ~200ms），尊重 prefers-reduced-motion
5. **不搞全站玻璃化**：「书香」暖墨纸感是这个项目的身份，玻璃是点缀不是基调

### D. 排版与细节（HIG 地基）
1. 标题负字距、正文 0 字距、小标签正字距；行高大标题紧、正文松（1.5+）
2. 正文对比度 ≥ 4.5:1，灰色小字不承担关键信息
3. i18n 完整：中英文切换每个页面无漏翻译、无 key 裸奔
4. 响应式 390px 不横向滚动、不裁切关键操作

## 二、执行步骤（Step 0 → 7，顺序执行）

### Step 0 — 基线环境跑通（不改业务代码）
1. `brew services start mysql`，建库 `library_system`
2. 按依赖顺序执行 sql/：init.sql → V2~V6 → mock_data.sql（幂等，可重复执行）
3. 复制 `application-local.properties.example` → `application-local.properties`，填本地密码 + 随机 JWT_SECRET（**此文件不进 git，先确认 .gitignore 覆盖**）
4. `mvn spring-boot:run`（local profile）起后端，`npm run dev` 起前端
5. 浏览器验证：能登录（验证码可从 Redis 取，dev 手法）、三个角色首页能打开
6. 产出基线：确认全栈可用才进 Step 1；此步不 commit（除非需要修 .gitignore）

### Step 1 — 全页面功能走查（浏览器实测，先记录后动手）
逐页面实测三个角色全部路由（读者 / 图书管理员 / 管理员 + 登录页 + 404）：
- 页面能否打开、数据能否加载、图表能否渲染
- 浏览器 console 有无报错、有无 404 请求
- 空数据 / 有数据两种状态下的显示
- 中英文各走一遍关键页面，记录漏翻译
- 390px 宽度抽查每个角色首页 + 最复杂页面
产出：`docs/audit/01-functional-issues.md`（问题表：# / 页面 / 现象 / 严重度 P0-P2）→ commit + push

### Step 2 — 设计审查（苹果设计师 + 液态玻璃 + 书香规范）
对全局（styles、App.vue、SideBar、Login 页）+ 每个业务页逐个审查：
- 对照第一章 A/B/C/D 四把尺子逐条过
- 重点：hover/active 反馈缺失、空态裸奔、loading 干等、字距行高、对比度、
  弹窗/下拉的玻璃材质、按钮层级（一屏多主按钮）、44px 热区、reduced-motion
产出：`docs/audit/02-design-issues.md`（问题表 + 每项给具体修复方向，标 P0-P2）→ commit + push

### Step 3 — 修复批次 A：全局与共享层
范围：styles/ 全部、App.vue、SideBar.vue、LoginView、StudentLoginView、404 页、
全局 transitions、共享小组件（空态/loading 样式统一）。
- 修完 `npm run build` 零错误 → commit + push（`v6.1 全局设计系统与登录页整改`）

### Step 4 — 修复批次 B：读者端
范围：views/reader/ 全部 11 个页面，按 01/02 问题清单逐项修。
- 修一个模式（如空态）grep 全读者端一次修完
- `npm run build` 零错误 → commit + push（`v6.2 读者端页面整改`）

### Step 5 — 修复批次 C：图书管理员端 + 管理员端
范围：views/librarian/ 6 页 + views/admin/ 13 页，同批次 B 纪律。
- `npm run build` 零错误 → commit + push（`v6.3 馆员端与管理员端整改`）
- 如清单显示工作量过大，可拆 2-3 个 commit，但每个都必须 build 通过再 push

### Step 6 — 回归走查 + 收尾修复
1. 全部页面重新实测一遍（含中英文、390px、空/有数据态）
2. 新发现的问题一次性收尾修复 → build → commit + push（`v6.4 回归修复`）
3. 后端如有改动：`mvn -q compile` + 跑一遍测试确认没破坏（`mvn test`）

### Step 7 — 交付
1. 更新 CHANGELOG.md（v6.0 条目）
2. 最终问题闭环表：|| # | 页面 | 问题 | 严重度 | 状态 | 修复内容 ||，总数闭环
3. commit + push，向用户汇报

## 三、禁止清单（不要干什么）

1. **不改后端业务逻辑 / API 契约 / 数据库 schema**。若显示问题必须动后端，先停下来向用户说明再动
2. **不删任何功能、字段、路由、i18n key**。只能新增和改良
3. **不换 UI 库、不重写架构、不引入新依赖**。液态玻璃用 CSS 实现，不装库
4. **不动「书香」设计语言基调**：暖墨色系（#2C3E50 / #C0785C / #F8F5F0）保留，不做全站玻璃化、不换色板
5. **不做大爆炸式重写**：改动用 patch 定点修改，不用整文件重写（防止丢已有功能）
6. **密钥文件不进 git**：application-local.properties / .env 一律 gitignore
7. **不确定的需求不猜**：记录到报告末尾「留给用户决定」清单
8. **不跳过 Step 顺序**，不边查边改（先查完 → 再审完 → 才开修）

## 四、怎么不出错（防错纪律）

1. **小步提交**：每批修改 → build 零错误 → commit → push，四件事绑定，缺一不可
2. **修改前工作区必须干净**：上一批没 commit 不开下一批
3. **批量同类问题一次修完**：修一个页面的空态，先 grep 全项目同类写法统一处理
4. **不信「看起来对」**：修复以 build 通过 + 代码复查 / 浏览器实测为准，不凭想象宣布修好
5. **浏览器走查结论要代码佐证**：页面上看到的问题，回到源码定位根因再改
6. **遇到基线阻断**（后端起不来 / 登录不进）：先修基线，基线问题单独 commit，不带业务改动
7. **同一路线失败 2 次**：停下输出诊断，换路线（如 mvn 慢 → 后台跑；浏览器登录卡 → 换 dev 配置），不硬闯
8. **i18n 修复**：zh-CN 和 en-US 成对改，改完 grep key 一致性
